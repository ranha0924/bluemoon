# 터지기 전에 — 가스안전 사건파일 (Before It Blows)

한국가스안전공사 **가스안전 AI 게임·영상 공모전** 출품용 작품 —
실제 가스안전 수칙과 통계(공사 공식 블로그 발췌)를 그대로 추리 게임의 단서·증언·추리 문항으로
옮긴 교육용 어드벤처다. 조사관 한세인이 두 건의 가스사고 파일을 맡는다.
모든 일러스트는 **Higgsfield AI**로, 대사·내레이션 음성은 **ElevenLabs** TTS 로 제작했고(둘 다 AI 생성),
게임은 의존성 없는 단일 HTML 파일이다.

| | 사건 | 무대 |
|---|---|---|
| CASE FILE #1 | **한여름 밤의 파열음** | 강변 캠핑장 '별무리'. 바비큐 중이던 그늘막에서 부탄캔이 터졌다 |
| CASE FILE #2 | **보이지 않는 손님** | 폭설에 갇힌 언덕 위 펜션 '설래원'. 냄새도 소리도 없이 손님들이 쓰러졌다 |

### 사건이 가르치는 것

- **사건 1 — 부탄캔** : 금지 수칙(삼발이보다 큰 조리기구 · 포일 감은 석쇠 · 병렬 사용과
  두 대 위 불판 걸치기 · 화기 근처 방치 · 직접 가열), 사용 후 연소기에서 분리, 권장사용기간 **3년**,
  보관은 **40℃ 이하**, 부풂·쉭쉭 소리는 파열 전조 — 만지지 말고 즉시 대피.
- **사건 2 — 보일러 일산화탄소** : 배기통 점검 **3종**(이탈 · 찌그러짐 · 이물질),
  CO는 **무색무취**(연료가스의 부취제와 다르다), CO경보기 교체주기 **5년**,
  보일러 점검 **연 1회 이상**, 한파에도 **2~3시간마다 환기**, 노랗거나 붉은 불꽃은 불완전연소 신호.

## 실행

`index.html`을 브라우저로 열면 바로 시작된다. 빌드 과정이나 서버는 필요 없다.
타이틀 → **로비(사건 선택)** → 프롤로그 → 허브 → 조사·심문 → 추리 → **사고 재현** → 진상 → 엔딩 순으로 진행된다.

### 오프라인 단일 파일판

**`dist/before-it-blows-offline.html`** 파일 하나에 이미지 23장·폰트 4벌·배경음악 2곡·대사 음성
96줄이 모두 들어 있다(약 20.3MB). `assets/` 폴더도 인터넷도 없이, 이 파일만 USB·메신저로 옮겨
더블클릭하면 똑같이 실행된다(오프라인 전시·수업용 — 메일 첨부는 용량 제한에 걸릴 수 있다). GitHub 에서 받을 때는 파일 화면의
**Download raw file** 버튼을 쓴다 — Raw 를 누르면 브라우저가 텍스트로 보여 준다.
PC 브라우저(Chrome·Edge·Whale 등) 기준이며, 휴대폰은 로컬 HTML 파일 열기가 기기마다
제각각이라 권하지 않는다.

이 파일은 `tools/build-offline.py`가 `index.html` + `assets/`로 만든 **생성 파일**이다.
`index.html`이나 에셋을 고쳤으면 다시 만든다.

```bash
python3 tools/build-offline.py            # 생성 (같은 입력이면 바이트까지 같은 결과)
python3 tools/build-offline.py --check    # 커밋된 파일이 최신인지 확인
python3 tools/verify-offline.py           # 빈 폴더 + 오프라인 file:// 로 전체 플레이 검증
```

폰트는 CSS 안의 `data:` URI 로, 이미지·음악·대사 음성은 실행되지 않는 base64 블록으로 실리고,
`index.html`의 `offURL()`이 이를 `blob:` URL 로 바꿔 쓴다. 이 판에서는 CDN 폴백을 끄므로
외부 요청이 0건이다. 폰트 라이선스(SIL OFL 1.1) 원문은 파일 머리 주석에 그대로 들어 있다.

이미지는 로컬 `assets/`를 먼저 쓰고, 파일이 없으면 원본 Higgsfield CDN(PNG)으로 자동 폴백한다.
폴백 URL은 `index.html`의 `CDN` 객체에 들어 있다.
두 경로 모두 실패하면 해당 `<img>`만 숨고 게임 진행은 그대로 이어진다.

## 사건 추가하기

엔진(`G`)은 시나리오 상수를 직접 참조하지 않고 **현재 선택된 사건 객체 `G.C`만** 본다.
그래서 새 사건은 `CASE1` / `CASE2`와 같은 모양의 객체를 하나 더 만들어 `CASES`에
등록하면 끝나고, 게임 로직은 손대지 않는다.

```js
const CASE3 = {
  no:3, name:"...", cover:"<이미지 key>", intro:"로비 카드 한 줄 소개",
  hubTitle:"...", hubWord:"펜션", backLabel:"펜션으로",   // 허브 표기
  talkBg:"<이미지 key>", rain:true,                       // 심문 배경 / 바람 소리
  needTesti:"t1", needLabel:"설아의 증언",                 // 추리 해금 조건
  CLUES:{...}, TESTI:{...}, ROOMS:{...}, PEOPLE:{...},
  PROLOGUE:[...], REVEAL:[...], DEDUCE:[...],
  deduceIntro:{...}, regroup:{...},
  // 선택: 빠른 조사 모드(로비 토글)용 대체 데이터 — 없으면 표준 데이터로 폴백
  fastPrologue:[...], fastReveal:[...], fastDeduce:[0,1,3],
  // 선택: 사고 재현 — 추리를 다 맞힌 뒤 진상 공개 직전에 끼는 행동 시뮬레이션
  SIM:{ bg:"<이미지 key>", title:"...", brief:"상황 설명",
    focus:[x,y,r],            // 선택: 스포트라이트 (없으면 생략)
    loop:"hiss",              // 선택: 루프 효과음 (현재 프리셋: 가스 누출음)
    need:1,                   // ok 행동을 몇 개 수행해야 성공인가 (1=택일형, N=전수행형)
    actions:[ { label:"행동", fb:"해설", ok:true }, ... ],  // 최대 4개, ok 없으면 오답
    success:"성공 배너 문구" },
  ending:{ img, title, text, recap:["엔딩 요약 카드에 찍힐 수칙", "..."] }
};
const CASES = { case1:CASE1, case2:CASE2, case3:CASE3 };
```

이미지를 쓰려면 `CDN` 객체에 같은 key를 추가하면 된다 (`IMG`는 `CDN`에서 자동 생성).
새 사건의 대사는 음성 파일이 없으므로 무음으로 나온다 — 엔진 수정은 필요 없다(아래 '대사 음성').
단서 수(`/8`), 증언 수(`/3`), 추리 문항 수는 데이터에서 세므로 사건마다 달라도 된다.
`ending.recap`은 최대 5줄 — 없으면 엔딩 요약 카드가 통째로 숨는다.
빠른 조사 모드 필드는 전부 선택 사항이다 — `fastPrologue`/`fastReveal`(3줄 컷씬),
`fastDeduce`(낼 문항의 DEDUCE 인덱스), 각 단서의 `fast`(1문장 요약).
없으면 그 부분만 표준 데이터로 폴백하고, 수첩에는 모드와 무관하게 `desc` 전체가 실린다.
`SIM`도 선택 사항이다 — 없으면 추리에서 곧장 진상 공개로 넘어간다. 재현은 두 모드에서
동일하게 재생되며, 학습용 자유 실험 공간이므로 **어떤 행동을 골라도 등급·촛불에는
영향을 주지 않는다** (엔진 불변식 — `SIM` 객체는 `G.wrong`/`G.hearts`를 건드리지 않는다).

### 3D 증거 조사

방의 스팟에 `{ label, inspect:"<모델 key>", needs:"<선행 단서>" }`를 넣으면
캔버스 3D 조사 화면이 열린다. 드래그해 물체를 돌리면 뒷면이 드러난다.

| 모델 key | 물체 | 뒷면에서 확인하는 것 |
|---|---|---|
| `can` | 부탄캔 | 바닥에 새겨진 제조일 — 권장사용기간 3년 초과 |
| `alarm` | CO경보기 | 뒷면 라벨의 제조연월 — 교체주기 5년 초과 |

두께·배율·앞면 무늬·각인 문구는 `INSPECT.MODELS` 표에만 있고,
회전·투영·발견 판정 로직은 모델과 무관하게 공용이다.

### 화면 배율

`#game`은 항상 1000×625 좌표계로 그려지고, 표시 크기만 `transform:scale()`로 맞춘다
(`fitStage()`가 `--s`를 갱신). 글자·여백·토스트가 프레임과 같은 비율로 줄어들기 때문에
화면 크기별 레이아웃 분기 없이 어디서나 같은 모양을 유지한다.

### 에셋 처리 내역

원본은 Higgsfield AI로 생성한 PNG이며, 웹 배포용으로 다음과 같이 변환했다.

- **배경 13장** — 2752×1536 원본 해상도 유지, WebP q82
  - 공통: `keyart` (타이틀 키비주얼)
  - 사건 1: `cover1` `bbq` `nextsite` `firepit` `store` `end1`
  - 사건 2: `cover2` `boilerroom` `rooftop` `guestroom` `kitchen3` `end2`
- **인물 10장** — 배경 제거 후 투명 여백을 잘라내고 높이 1000px로 축소, WebP q86 (알파 유지)
  - 공통: `detective`
  - 사건 1: `boss` `parttime` `camper` `daughter`
  - 사건 2: `host` `keeper` `guest` `child` `inspector`

여백을 잘라낸 덕에 `object-fit:contain` 기준으로 인물이 화면을 꽉 채우고,
`object-position:bottom`으로 대화 상자 위에 정확히 붙는다.

- **대사 음성 96줄** — ElevenLabs 원본(mp3 128kbps 모노)을 화자 단위로 음량을 맞춰
  (모노 측정 약 −21 LUFS, 피크 −1.5 dBTP 이하) 앞뒤 무음을 다듬고 48kbps 모노 mp3 로 인코딩.
  줄마다 정규화하지 않는다 — 속삭임과 외침이 같은 크기가 되어 연기가 눌리기 때문이다.

- **폰트 4벌** — 나눔명조 700/800(제목), Noto Sans KR 400/700(본문). Google Fonts 배포본을
  `index.html`의 전체 문자 + ASCII 로 서브셋해 woff2 로 동봉했다(834자 기준 총 ~0.4MB).
  덕분에 **인터넷 없이도(오프라인 전시·수업) 동일하게 렌더**되고 외부 요청이 0건이다.
  라이선스는 SIL OFL 1.1 — 원문을 `assets/fonts/OFL-*.txt`로 함께 둔다
  (오프라인 단일 파일판에는 같은 원문이 파일 머리 주석으로 들어간다).
  시나리오에 새 글자를 추가하면 `tools/build-fonts.sh`로 다시 잘라야 한다.

## 대사 음성

게임이 글로 보여 주는 이야기는 전부 소리로도 나온다 — 대화 화면의 모든 줄(프롤로그·진상 공개·
추리 도입·재정비의 인물 대사와 내레이션, 단서 설명), 심문 답변, 엔딩 글, 그리고 빠른 조사 모드의
대체 대사까지 96줄이다. 글이 뜨면 재생되고, 다음 줄로 넘기거나 화면이 바뀌거나 답변 패널을
닫으면 멈춘다. 허브의 사운드 버튼으로 효과음·배경음악과 함께 꺼진다.

| 무엇을 | 누구 목소리로 | 줄 수 |
|---|---|---|
| 인물 대사 · 심문 답변 | 그 인물 (아래 배역표) | 58 |
| 내레이션 · 엔딩 글 | 내레이션 | 6 |
| 단서 설명 (빠른 조사용 요약 포함) | 탐정 한세인의 독백 | 32 |

심문 화면의 **질문 선택지(탐정의 질문 24줄)** 는 싣지 않았다 — 질문을 먼저 읽으면 정작 증인의
답변 음성이 2초가량 늦게 시작해, 글을 읽고 바로 닫는 사람은 답변을 듣지 못한다. 음성은
`tools/voice/masters/`에 합성해 두었으므로(`script.json`의 `ship:false`) 넣기로 하면 재합성 없이 켤 수 있다.
추리 문항·해설, 사고 재현의 지문 같은 퀴즈 화면의 글은 음성 대상이 아니다.

- **실행 중에는 아무것도 합성하지 않는다.** ElevenLabs TTS(`eleven_v4`)로 한 번 합성해
  `assets/voice/<키>.mp3`로 커밋한 파일을 틀 뿐이다 — API 호출도 외부 요청도 없다.
- **키는 내용 주소다.** `화자|대사 본문`의 FNV-1a 32bit 해시(16진 8자리)가 파일 이름이다.
  대사를 한 글자라도 고치면 키가 달라져 **그 줄만 무음**이 된다 — 고친 문장에 옛 음성이 나오는
  일도, 없는 파일을 요청하는 일도 없다(형광펜 `[[ ]]` 마커는 키에 들어가지 않는다).
- **다시 합성하려면 API 키가 필요하다.** 그래서 원본(`tools/voice/masters/`)과 낭독 대본을
  함께 둔다 — 음량·비트레이트·앞뒤 여백은 키 없이도 `encode`로 다시 맞출 수 있다.

```bash
python3 tools/build-voice.py check       # 대사 ↔ 목록(VOICE_HAVE) ↔ 파일 ↔ 대본 ↔ 원본 정합성 (해시 대조 포함)
python3 tools/build-voice.py encode      # 원본 → assets/voice (화자별 음량 통일, 48kbps 모노)
python3 tools/build-voice.py manifest    # index.html 의 VOICE_HAVE 한 줄 갱신
python3 tools/build-voice.py prune       # 대사가 바뀌어 주인이 없어진 assets/voice 파일 삭제
python3 tools/verify-voice.py            # check + 게임 안에서 실제 입력으로 재생·정지 검증 (서버 8899 필요)
ELEVENLABS_API_KEY=… python3 tools/build-voice.py fetch   # 새로 합성 (키는 환경 변수로만)
```

`check`는 파일 이름만 보지 않는다 — `takes.json`에 적어 둔 원본·탑재 파일의 sha256 과 대조해
이름은 맞는데 내용이 뒤바뀐 파일, 대본이나 배역을 바꿔 놓고 다시 합성하지 않은 원본을 잡는다.
대사를 고쳐 그 줄의 음성을 포기하기로 했다면 `prune` → `manifest` → `check --allow-unvoiced` 순이다.

낭독 대본(`tools/voice/script.json`의 `tts`)은 화면 표기와 다르다 — 숫자와 단위를 한글로
풀고(`60℃`→육십 도, `2~3시간`→두세 시간, `6.75배`→육 점 칠오 배), 지문 `(고개를 떨군다)`는
읽지 않고 연기 태그(`[sighs]`)로 바꿨다. 합성 뒤 모든 줄을 음성→텍스트로 되받아써 대조했다

## 조작

마우스(터치)와 키보드 어느 쪽으로도 전 과정을 진행할 수 있다.

| 키 | 동작 |
|---|---|
| `Enter` / `Space` | 대화 진행 (첫 입력은 타이핑 완성, 다음 입력에 다음 줄) · 포커스된 카드 선택 · 답변 닫기 |
| `Tab` | 버튼·카드(사건/방/인물) 사이 포커스 이동 |
| `1` ~ `4` | 추리·사고 재현의 선택지 (버튼의 번호 각인과 대응) |
| 방향키 | 3D 증거 조사에서 물체 회전 (누르고 있기 지원) |
| `Esc` | 수첩·답변 패널 닫기 (추리 화면의 [수첩]도 동일) |

키를 누르고 있어도 한 번만 입력된다(반복 무시). 정답 연출 중에는 선택지가 잠긴다.

## 학급 설문 (게임 내장)

수업·부스에서 교육 효과를 재는 사전·사후 5문항 설문이 **게임 안에 들어 있다** — 별도
페이지가 없다. 로비의 **[학급 설문]** 버튼으로 열리는 전면 오버레이이며, 교사 배포용
딥링크는 `?survey=pre`(사전 바로 시작) / `?survey=post`(사후) / `?survey=1`(입구)이다.
오버레이를 닫으면 URL 에서 `survey` 파라미터가 지워져, 엔딩의 **[처음부터 다시]**(reload)가
설문을 다시 띄우지 않는다(`?fast`는 그대로 보존).

- **사전** — 답만 저장하고 점수·정답을 보여 주지 않는다(사후 측정 오염 방지). 채점 코드는
  사후 경로에서만 호출된다.
- **사후** — 같은 5문항 + 재미/추천 5점 + 주관식. 제출하면 점수, 문항별 해설(게임 속 근거
  위치), 사전 대비 변화(+n)가 나온다. 서버가 없으므로 결과는 기기에만 남고, 학생이
  **결과 요약 한 줄을 복사**해 학급 게시판·메신저로 내면 교사가 집계한다.
- 저장은 `localStorage` 키 `hansein.survey.v1` 하나(차단 환경은 메모리 폴백 + 안내).
- 설문이 열려 있는 동안 배경 게임은 `inert` 로 잠긴다(Tab·클릭 차단, Esc 는 닫기).
  설문 문구도 `index.html`의 일부이므로 새 글자를 넣으면 `tools/build-fonts.sh` 재실행 —
  게임 본문과 같은 일반 규칙이다. 고쳤으면 `python3 tools/verify-survey.py`를 돌린다.

## 진행 방식

1. **사건 선택** — 로비에서 사건 파일을 고른다. 사건을 시작할 때마다 단서·증언·촛불·오답이 초기화된다.
   로비의 **[빠른 조사]** 토글을 켜면 프롤로그·진상이 3줄로, 단서 대사가 1문장으로, 추리가 3문항으로
   줄어 한 사건이 약 4~5분에 끝난다(전시·체험용). 설정은 브라우저에 저장되어
   **[처음부터 다시]** 뒤에도 유지된다. 전시·키오스크 배포 링크에는 `?fast=1`을 붙이면
   저장된 설정보다 우선해 늘 빠른 모드로 시작하고(`?fast=0`은 강제 꺼짐), 관람객이 자리를
   뜨면 **무입력 80초에 안내 토스트, 90초에 타이틀로 자동 복귀**해 다음 사람이 늘 처음
   화면에서 시작한다(타이틀·학급 설문 중에는 셈을 쉰다)
2. **조사** — 방 4곳에서 단서 8개를 모은다. 일부 스팟은 선행 단서를 찾아야 열리는 3D 증거 조사다.
   허브의 **[로비로]** 버튼으로 언제든 사건 선택으로 돌아갈 수 있다(재진입 시 진행은 초기화)
3. **심문** — 인물 4명에게 질문한다. 일부 질문은 관련 단서나 증언을 먼저 확보해야 열린다
4. **추리** — 단서 8개 + 지정 증언을 갖추면 4문항 추리가 열린다. 우상단 **[수첩]**으로
   문항 중에도 모은 단서·증언을 다시 볼 수 있다. 촛불 3개가 모두 꺼지면 재정비 대사 후
   촛불을 되찾고 계속한다 — 이미 골랐던 오답은 잠긴 채 남아 같은 실수로 촛불이
   깎이지 않는다
5. **사고 재현** — 추리를 모두 맞히면 사고 순간으로 돌아가 직접 행동을 고른다.
   사건 1은 택일형(부풀며 쉭쉭대는 캔 앞에서 무엇을 할 것인가), 사건 2는 전수행형
   (CO 중독 의심 상황의 조치 3가지를 모두 수행). 오답은 붉은 화면과 해설로 배우고,
   몇 번을 틀려도 등급에는 영향이 없다. 추리·재현 화면의 우상단 **[로비로]**는 실수
   방지를 위해 **두 번 눌러 확정**한다(첫 클릭 후 3초 안에 한 번 더) — 부스에서 관람객이
   중간에 떠났을 때 운영자가 새로고침 없이 처음으로 되돌리는 동선이다
6. **엔딩** — 진상 컷씬 뒤 **'오늘의 가스안전 수칙'** 요약 카드가 그 사건의 핵심 수칙 5줄을 정리해 준다.
   오답 횟수에 따라 **S — 가스안전 마스터 / A — 우수 탐정 / B — 진실 도달** 등급 (사건별 독립 판정).
   **[수사관 임명장]** 버튼은 사건명·등급·오늘의 수칙·날짜가 찍힌 임명장 PNG(1500×2120)를
   그 자리에서 그려 내려받는다 — 발급 명의는 게임 속 '한세인 탐정사무소'이며, 캔버스에
   벡터와 텍스트만 그리므로 오프라인(`file://`)에서도 동작한다. 엔딩에서
   **[다른 사건 파일]**로 로비에 돌아갈 수 있다
